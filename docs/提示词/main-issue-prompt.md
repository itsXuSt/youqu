# YouQu 自动化测试编排 — 主 Issue 提示词

## 标题与标签

- 标题：`[自动化测试] {应用名} 全量 YAML 用例回归执行`
- labels：`automation`, `youqu`
- assignee：`youqu-orchestrator`

---

## 目标

对 **{应用名}** 的全量 YAML 用例进行回归执行：先获取用例信息并按模块分组，再为每个模块创建子 Issue 分派执行，最后汇总结果。

## 环境信息

| 配置项 | 值 |
|--------|-----|
| 项目路径 | `{PROJECT_ROOT}/autotest/` |
| 应用二进制 | `{APP_BINARY}` |
| 进程名 | `{APP_NAME}` |
| 执行 Agent | `youqu-executor` |

## 职责

本 Issue 不执行测试。只做三件事：**信息获取 → 编排分派 → 报告汇总**。

---

## 阶段 1：信息获取

### 获取用例全量信息

```
yaml_list_tests()
```

返回的 `tests` 列表中每条记录包含 `id`、`module`、`feature`、`tags`、`name`、`app`。

`stats.modules` 给出每个模块的用例数，用于分批规划。

### 按模块分组并输出清单

将 `tests` 按 `module` 字段分组。`module` 为空的归入「未分类」。

在本 Issue 下评论，发布分组结果：

```
## 模块分组

应用: {应用名} | 用例总数: {M} | 模块数: {N}

| 序号 | 模块 | 用例数 | L1 | L2 | L3 | 测试 ID 范围 |
|------|------|--------|----|----|----|-------------|
| 1 | 播放 | 23 | 12 | 8 | 3 | test_play_001 ~ test_play_023 |
| 2 | 设置 | 15 | 8 | 5 | 2 | test_settings_001 ~ test_settings_015 |
| 3 | 未分类 | 5 | 4 | 1 | 0 | test_misc_001 ~ test_misc_005 |
| **合计** | | **43** | **24** | **14** | **5** | |
```

---

## 阶段 2：编排分派

### 为每个模块创建子 Issue

标题：`[子任务] {应用名} - {模块名} ({N}个)`

labels：`automation`, `youqu`, `sub-task` | assignee：`youqu-executor`

子 Issue Body：

```
parent: #{主Issue编号}

## 参数

| 参数 | 值 |
|------|-----|
| APP_BINARY | {APP_BINARY} |
| APP_NAME | {APP_NAME} |
| MODULE | {MODULE} |
| TEST_IDS | module:{MODULE} |

## 用例清单

{逗号分隔的测试 ID 列表}
```

> 子 Issue 只需给出参数和用例清单。执行 Agent 必须加载 `youqu-case-runner` 技能，知晓完整执行流程和约束。

### 注意

`yaml_run_batch` 单线程串行（`MAX_CONCURRENT=1`），执行 Agent 应逐个认领子 Issue，完成一个再认领下一个。

---
