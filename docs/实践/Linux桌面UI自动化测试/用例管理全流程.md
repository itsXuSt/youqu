# 用例管理全流程

## 概述

本文档描述 YouQu 框架中用例管理的完整生命周期：从 PMS 平台上的测试设计文档，到本地可执行的 Python 测试用例，再到执行结果回填。

**核心认知**：YouQu 不会自动从 xlsx/csv 生成 Python 测试文件。框架中 CSV 的角色是**标签元数据层**，不是用例逻辑定义。

## 用例存在三处

| 位置 | 格式 | 内容 | 作用 |
|------|------|------|------|
| PMS 平台 | 数据库 | 用例标题、步骤、预期、优先级、类型、设备类型 | 测试设计与管理 |
| `casefile/` 目录 | xlsx/csv | PMS 导出的完整测试设计文档 | 人工设计阶段产物，框架不消费 |
| 本地 `apps/` 目录 | CSV + Python | CSV 存标签，Python 存步骤逻辑 | 框架执行的直接输入 |

### casefile 目录

某些项目的源仓库中存在 `autotests/casefile/` 目录，包含从 PMS 导出的 xlsx/csv 文件，列标题为：

```
用例编号,所属产品,所属模块,相关需求,用例标题,前置条件,步骤,预期,...
```

这些是**测试设计文档**，用于人工评审和设计交流。它们不是框架的输入文件，不能被框架直接消费。

## 用例数据流

```
┌──────────────────────────────────────────────────────────────┐
│  PMS 平台 (pms.uniontech.com)                                  │
│  ├── 用例库/产品库: 标题、步骤、预期（自然语言）                  │
│  └── 用例标签: 级别、类型、设备类型、上线状态                     │
└───────────────┬──────────────────────────┬────────────────────┘
                │                          │
    pmsctl ──pms2csv                 send2pms ── 结果回填
    (拉取标签)                        (回填 pass/fail)
                │                          │
                ▼                          │
┌──────────────────────────────────────────┼──────────────────┐
│  本地 CSV 标签文件 (apps/autotest_xxx/xxx.csv)                │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 脚本ID,PMS用例ID,用例级别,用例类型,设备类型,跳过原因,...  │  │
│  │ 001,1693083,L3,FUNC,,skip-未适配,...                    │  │
│  │ 002,1693084,L2,FUNC,,,fixed-V25,...                     │  │
│  └────────────────────────────────────────────────────────┘  │
│         ▲                          │                          │
│         │ csvctl ──pyid2csv        │ runtime (conftest.py)    │
│    (py→csv 同步ID)           动态标记 skip/fixed/removed      │
│         │                          ▼                          │
│  可执行 Python 测试文件 ────────────┘                          │
│  (apps/autotest_xxx/case/test_xxx_001.py)                    │
│  (手写 Widget 方法 + 步骤逻辑 + 断言)                          │
└──────────────────────────────────────────────────────────────┘
```

## 完整工作流

### Step 1：初始化项目并创建 APP 工程

```bash
# 创建框架项目
youqu-startproject my_project
cd my_project
bash env.sh

# 创建 APP 工程（生成 PO 设计模式骨架）
youqu manage.py startapp autotest_my_app
```

生成的目录结构：

```
apps/autotest_my_app/
├── widget/
│   ├── base_widget.py      # 方法基类，继承 Src（获得 dog/ocr/click 工具链）
│   ├── my_app_widget.py    # 方法出口类，封装具体操作
│   └── ui.ini              # ButtonCenter 坐标配置
├── case/
│   ├── base_case.py        # 用例基类，继承断言模块
│   └── test_mycase_001.py  # 用例模板
├── mycase.csv              # CSV 标签文件（标题行由框架自动写入）
├── my_app_assert.py        # 自定义断言类
├── config.py               # 应用配置
└── conftest.py             # pytest fixture 插件
```

### Step 2：编写 Widget 方法（封装操作）

所有应用交互需要先封装为 Widget 方法，再被用例调用：

```python
# widget/my_app_widget.py
from apps.autotest_my_app.widget.base_widget import BaseWidget
from src import log

@log
class MyAppWidget(BaseWidget):
    """应用方法主类"""

    def click_xxx_by_attr(self):
        """通过属性定位点击某按钮"""
        self.dog.find_element_by_attr("Btn_xxx").click()

    def find_xxx_by_image(self):
        """通过图像识别定位某元素"""
        return self.find_image("xxx.png")
```

### Step 3：编写测试用例

用例文件命名遵循 `test_<功能名>_<三位ID>.py` 格式：

```python
# case/test_mycase_001.py
from apps.autotest_my_app.case.base_case import BaseCase
from apps.autotest_my_app.widget.my_app_widget import MyAppWidget

class TestMyCase(BaseCase):

    def test_mycase_001(self):
        """my test case description"""
        MyAppWidget().click_xxx_by_attr()
        self.assert_process_status(True, "expected-process")
```

### Step 4：同步用例 ID 到 CSV

```bash
# 通过配置文件（推荐，设置一次即可）
# 在 setting/globalconfig.ini 中配置：
# [csvctl]
# PY_ID_TO_CSV = yes
youqu manage.py csvctl

# 或通过命令行参数
youqu manage.py csvctl -p2c -a apps/autotest_my_app
```

这会扫描 `test_*.py` 文件的 ID，自动在 CSV 中创建/清理对应行，确保每个 Python 用例在 CSV 中都有一条记录。

### Step 5：配置 PMS 集成

编辑 `setting/globalconfig.ini`：

```ini
[pmsctl]
; PMS 登录账号
PMS_USER = ut001234
PMS_PASSWORD = your_password

; 用例来源：caselib（用例库）或 testcase（产品库用例）
CASE_FROM = caselib

; 测试单 ID（用于结果回填）
TASK_ID =

; 结果回填方式：async（异步）/ finish（结束后）/ 空（不回填）
SEND_PMS = async

; 触发方式：auto（自动）/ hand（手动）
TRIGGER = auto

[pmsctl-pms_link_csv]
; key = 本地 CSV 文件名（不含 .csv）
; value = PMS 上对应模块的 ID
; 从 PMS URL 获取：https://pms.uniontech.com/caselib-browse-81.html → ID = 81
music = 81
movie = 82
```

### Step 6：从 PMS 拉取标签

```bash
# 通过配置文件（配置了 pmsctl-pms_link_csv 后）
youqu manage.py pmsctl -p2c -a apps/autotest_my_app

# 或完全通过命令行传参
youqu manage.py pmsctl -p2c -u ut001234 -p my_password -plc "music:81/movie:82"
```

#### pms2csv 同步的具体数据

| PMS 字段 | 写入 CSV 列 | 说明 |
|----------|-------------|------|
| 用例优先级 (`pri`) | `用例级别` | L1/L2/L3/L4 |
| 用例类型 (`type`) | `用例类型` | FUNC/PERF/STR/SEC/CTS/API（由 `pmsmark.ini` 映射） |
| 是否 BUG 转用例 (`caseSource`) | `一二级bug自动化` | BUG 或空 |
| 设备类型 (`deviceType`) | `*设备类型` | PPL/COL 或空 |
| 上下线对象 (`lineCD`) | `*上线对象` | CICD 或 skip-下线CD |

**pms2csv 不同步**：用例标题、前置条件、测试步骤、预期结果——这些内容以自然语言存在于 PMS 平台，需要人工理解后转化为 Python 代码。

### Step 7：执行测试

```bash
# 本地执行
youqu manage.py run -a apps/autotest_my_app

# 按标签过滤
youqu manage.py run -a apps/autotest_my_app -t "L1 and FUNC"

# 远程分布式执行
youqu manage.py remote -c user@ip:password -a apps/autotest_my_app
```

执行时，框架的 `conftest.py` 在用例收集阶段：
1. 扫描 `apps/` 下的 CSV 文件
2. 将 CSV 行与测试函数按三位 ID 匹配
3. 动态应用 skip/fixed/removed 标记
4. 附加 Allure 标签
5. 根据 `--task_id` / `--suite_id` 过滤关联用例

### Step 8：结果回填 PMS

```bash
# 自动回填（配置 SEND_PMS = async 后，执行时自动回填）
youqu manage.py run -a apps/autotest_my_app --task_id 20747

# 手动回填（配置 TRIGGER = hand 后，执行后手动触发）
youqu manage.py pmsctl --send2task yes --task_id 20747
```

每条用例执行后在 `report/pms_{task_id}/` 下生成 JSON 结果文件，包含 pass/fail 状态，send2pms 将其 POST 到 PMS。

## 常见问题

### Q: casefile 里的 xlsx 能直接用来跑测试吗？

**不能。** casefile 是 PMS 导出的测试设计文档（含步骤描述），不是框架的输入格式。你需要：
1. 理解 xlsx 中的用例设计
2. 编写 Widget 方法封装操作
3. 编写 Python 测试用例调用 Widget 方法
4. 通过 csvctl 同步 ID 到 CSV
5. 通过 pmsctl 从 PMS 拉取标签填充 CSV

### Q: pms2csv 能把 PMS 上的用例步骤自动转成 Python 代码吗？

**不能。** pms2csv 只同步标签元数据（级别、类型、设备类型等），不同步用例步骤内容。将自然语言的测试步骤转化为可执行的 Python 代码，需要人工完成。

### Q: CSV 和 Python 测试文件，谁先谁后？

**Python 先，CSV 后。** 推荐流程是先编写 Python 测试文件，然后通过 `csvctl -p2c` 将用例 ID 同步到 CSV，再通过 `pmsctl -p2c` 从 PMS 拉取标签到 CSV。

### Q: 如何知道 PMS 模块 ID？

打开 PMS 上对应模块的用例库页面，URL 中包含数字 ID：
- 用例库：`https://pms.uniontech.com/caselib-browse-81.html` → ID 为 `81`
- 产品库用例：`https://pms.uniontech.com/testcase-browse-14.html` → ID 为 `14`
